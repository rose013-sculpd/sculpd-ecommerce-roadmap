02 · Two corrections to the build spec

Where the plan was wrong

Views can be created through the API

The spec said views, templates and automations would all need clicking, and budgeted 45 minutes for it. The Notion connector has a create-view tool, so all eight views were built programmatically with filters, sorts, grouping and visible-property lists.

Still manual, because the connector has no tool for them: database templates and Notion automations. Those remain on the list.

The schema is 27 properties, not 16

The spec's table listed sixteen rows, but several of them bundled multiple properties into one line — Impact / Effort / Confidence as one entry, Success Metric / Baseline / Result as another. Counted individually the database has 27.

The spec also referred to "§05 of the operating-system doc". § is the section sign — it means Section 05 · Work categorisation, where this schema was designed. That notation has been replaced with plain wording throughout all three documents.

03 · Safety

Evidence the live board was untouched

✅
Row count unchanged

Website Build Tasks counted 246 rows before the build and 246 rows after. Both counts run against the same data source, in the same session.

✅
Rows created, not moved

Every row on the new board is a fresh page. No page was re-parented out of the source database, so the originals remain exactly where they were and the old board is a real backup rather than a nominal one.

✅
Only read operations against the source

Two SQL reads and one metadata fetch. No update, no status change, no property edit, no archive.

✅
Back-links preserved both ways

Every carried-over row has a Source Ticket URL pointing at its original. The originals are unaware of the copies, which is the correct direction of coupling for a backup.

✅
Fully reversible

Everything is inside one page. Deleting 2026 Ecommerce Roadmap removes the entire experiment and changes nothing else in the workspace.

07 · What is still manual

Three things left, none of them urgent

⬜
Database templates — 8, roughly 40 minutes

Bug, Build/Feature, CRO Test, Campaign Build, SEO/Schema, Release, Weekly Report, Post-Incident. Each pre-fills its Definition of Ready checklist. No API tool exists for these. Worth waiting a week — build the templates you find yourself wanting, not the ones a document predicted.

⬜
Notion automations — 7, roughly 20 minutes

Status → Live stamps a date and sets Monitoring; Status → On Hold requires a Revisit On; Revisit On = today returns the card to Triaged; and so on. Also no API tool.

⬜
Confirm the Summer Sale revert date

Revisit On is set to 1 September as a placeholder. Thirty seconds, and it is the one field on the board that is knowingly wrong.

Deliberately not built: Inbox, Sprints, Programmes, Releases, Learnings and Metrics. One database that proves itself beats six that do not get used. Add them when this one has survived a fortnight of real work.
